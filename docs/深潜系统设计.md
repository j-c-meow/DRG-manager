## 一、系统总则（解锁 / 刷新 / 锁定）

### 1.1 定位

深潜（官方名：**Deep Dive 深潜** / **Elite Deep Dive 精英深潜**）= 每现实周 1 次的"红色订单"：一条贯穿三阶段的连续任务链，本周修正器全阶段生效，奖励大额且**必含空白模组**——与 B-3 模组抽卡（三提石任务→空白模组→锻造台 3 选 1）构成双系统联动，是空白模组的**最稳定周常来源**。

### 1.2 解锁门槛

| 条件 | 判定 | 出处 |
|---|---|---|
| 任一矿工晋升 ≥1★（`miners.some(m => m.stars >= 1)`） | **普通深潜**终端亮灯 | 对齐原作"晋升后解锁深潜终端"；矿工 `stars` 字段游戏.html 已有（名册对象），晋升框铜→红已实装 |
| 任一矿工晋升 ≥3★（`m.stars >= 3`） | **精英深潜**终端亮灯（与普通同周并行、独立进度） | 对齐原作"精英深潜需 3★ 矮人"；判定同款复用 |
| **深潜强制四职业满编**（侦察/工程/枪手/钻机各 1 人，4/4） | 缺员（含住院）无法开潜；士气 <30 弹警告 | 用户拍板 2026-09-13；名册 4 人=四职业，正好满编 |

自然节奏：晋升需 Lv25 + 晋升费 800×1.9^★ 代币，解锁深潜时玩家通常已过平台 Lv7-9（危4-5 常态），与深潜的危4 起步强度同频，无需额外平台等级门槛。

### 1.3 周刷新与锁定规则（用户拍板口径）

- 按**现实自然周**刷新：记录 **ISO 周号**（如 2026-W37），**周一 0 点（本地时区）自动换新**——新修正器、新三阶段、进度清零。
- **双轨并行（用户拍板 2026-09-13）**：普通深潜与精英深潜同周各自独立刷新、独立记录进度（随机种子 = ISO 周号 ×10 + 变体号），互不挤占。
- **失败可重打当前阶段**：阶段内失败 = 该阶段进度清零重打，**已完成阶段的奖励保留**（已入账不回滚）。
- **通关锁定到下周**：三阶段全清 → 本周深潜完结，按钮变"已通关"，显示倒计时至下周一。
- **跨周未通关作废**：未领的阶段奖励、未打的阶段一律不结转（新一周修正器不同，旧进度无意义）。
- 阶段必须**顺序推进**：阶段 N 未通关前，阶段 N+1 不可派遣。

### 1.4 派遣与结算规则（对齐现有核心循环）

- 每阶段 1 个连续长任务；上一关归队后下一关才开闸。**深潜小队强制四职业满编（4/4），缺员含住院不得开潜**（用户拍板 2026-09-13）。
- **深潜任务常规产出全额结算（用户拍板 2026-09-13，取消 ×0.5"风险费"折算）**：周常限次内容理应高奖励；契合职业当关另有加成（见 §二）。
- 深潜产出**照常计入季度 KPI**（现有结算已按墨菱石累计 `S.kpi.done`，天然兼容）。
- **阶段失败条件**（满足其一即中止，重打该阶段）：
  1. 本阶段累计**重伤入院 ≥2 人次**；
  2. 任务结算后**全队平均士气 <25**。
- 失败无额外惩罚：无死亡、无辞退，账单按既有医疗站口径照付（危5 档），硝石补给照扣——重打成本 = 时间 + 硝石 + 医疗账单，仅此而已。
- 通关时向战役线发进度：`campProgress('dive', '', 1)`（战役系统"通关深潜"目标钩子，接口与 `claimKPI` 同款）。

## 二、双轨结构：普通深潜 + 精英深潜（用户拍板 2026-09-13）

每现实周**同时**刷新两条独立的深潜链：**3 个阶段、每阶段 1 个连续长任务（共 3 个任务）**；每通过一关立刻发 1 份阶段奖励（全链共 3 份），三关全清再发 1 份通关大额奖励。两条链进度互不影响、可同周全打。

| 变体 | 解锁 | 阶段任务 → 契合职业 | 危险档 | HazardBonus | 单任务时长系数 | 修正器抽取 |
|---|---|---|---|---|---|---|
| 普通深潜 Deep Dive | 任一矿工 ≥1★ | 采矿探险→**侦察兵** → 消灭任务→**枪手** → 执勤护送→**钻机手** | 4 / 5 / 5+ | 2.00 / 2.33 / **2.66** | ×2.5 | 1 增益 + 2 减益 |
| 精英深潜 Elite Deep Dive | 任一矿工 ≥3★ | 定点提取→**侦察兵** → 消灭任务→**枪手** → 就地精炼→**工程师** | 5 / 5+ / 5++ | 2.33 / **2.66 / 3.00** | ×2.5 | 1 增益 + 3 减益 |

设计理由：

1. **[1,1,1] 三关制**：对齐原作"深潜=三段各一关、连续推进"（用户拍板）；每关 1 个长任务，上一关归队才开下一关，中途可在名册换人（不清进度）。
2. **时长 ×2.5**：让"每关都是一个大活"。换算（满编 4 人、士气 50、无事件修正，普通深潜）：
   - 阶段1：采矿探险 348 ×0.51×2.5 = 444 游戏分 ≈ **7.4 现实分钟**
   - 阶段2：消灭任务 528 ×0.51×2.5 = 673 ≈ **11.2 分钟**
   - 阶段3：执勤护送 576 ×0.51×2.5 = 734 ≈ **12.2 分钟**
   - **全程 ≈ 31 现实分钟（满编）/ ≈ 61 分钟（单人）**；精英深潜同类 ≈ 27 分钟（满编）。中途可下线（阶段进度持久化）。
3. **双轨分工**：普通=每周必做的稳定模组来源（空白模组 ×5）；精英=毕业玩家的高压高回报（空白模组 ×4 + 大额功绩点 + 顶级档淬炼保底），修正器多一条减益，周体验必然不同。
4. **超档系数（已拍板保留 2026-09-13）**：2.66 = 危5+0.33（"危6"）、3.00 = 危5+0.66（"危7"），主矿物 ×3.23 / ×3.75、账单 665 / 750。用户原话："数值后期必然膨胀，原版环境还有 5++ 难度"——保留，不回退。
5. **事件密度上探**：常规危4-5 期望 1.65/次 → 深潜 1.8-2.0/次 + 第三关开闸必发 1 事件，贴近原作"深潜步步惊心"。
6. **强制四职业满编 + 契合职业（用户拍板 2026-09-13）**：深潜小队固定 4 人=四职业各一，缺员（含住院）不能开潜——用硬约束逼出"全职业协作"的原作体验，顺带抬升医疗站价值。每关设一个契合职业，当关加成：采矿探险/定点提取→侦察兵（主矿物产出 +10%）、消灭任务→枪手（事件检定 +10%）、执勤护送→钻机手（任务时长 -10%）、就地精炼→工程师（任务时长 -10%）；契合加成与模组/士气乘法叠加。

### 4.2 空白模组收集节奏推算（联动 B-3 v1.2 全池 99 条）

**每周空白模组进账**：普通深潜 **5 个/周**（1+1+2+通关 1）+ 精英深潜 **4 个/周**（1+1+1+通关 1，双轨拍板后新增）+ 三提石任务（任务板偶刷，按权重估 0.5-1 个/周）≈ **9.5-10 个/周**。

抽卡模型（B-3 v1.2 已拍板规则：全池 99 条随机 3 选 1、**抽到已拥有 = 免费重抽**、10 抽保底 T1）：

- **现行口径**：免费重抽保证"每次抽卡必得新模组" → 集齐 99 条 = 99 抽 → 99 ÷ 9.5 ≈ **10 周（约 2.5 个月）**；10 抽保底让 T1 毕业件至多 10 抽一个，顶级档获取远快于全收集。
- 参考（非现行规则）：若改回"允许重复 + 折算 credits"，集齐期望 ≈ (99/3)×H₉₉ ≈ 33×5.2 ≈ **171 抽 ≈ 18 周**。
- **前 4 周体验**：每周进账 9-10 条新模组，首月即可开出 35+ 模组、各职业凑齐 1-2 件 T1——前期爽感密集，长线留给收集党。

结论：**双轨深潜合计约 10 模组/周，"全收集"落在约 2.5 个月**，与武器凭证全图鉴（2-3 个月）、精英支援位（3-4 个月）基本同频收官；若想拉长收集线，优先下调精英深潜空白模组投放（4→2）或三提石刷新率，不动阶段奖励结构。

/* —— ISO 周号：周一 0 点（本地时区）为一周起点 —— */
function isoWeekKey(d = new Date()){
  const t = new Date(d.getFullYear(), d.getMonth(), d.getDate());   // 本地 0 点
  const day = (t.getDay() + 6) % 7;                                 // 周一=0 … 周日=6
  t.setDate(t.getDate() - day + 3);                                 // 移到本周周四（ISO 定义）
  const y0 = new Date(t.getFullYear(), 0, 1);
  const week = Math.ceil((((t - y0) / 864e5) + 1) / 7);
  return t.getFullYear() * 100 + week;                              // 例：202637
}

/* —— 启动 / 每帧低频调用：跨周检测 —— */
function refreshDive(){
  const wk = isoWeekKey();
  if(!S.dive || S.dive.week !== wk){          // 跨周 → 一切作废，换新
    S.dive = {
      week: wk,
      mods: rollWeeklyMods(wk),               // 确定性抽取：1 增益 + 2 减益
      cleared: [false, false, false],         // 阶段通关状态（奖励随首次通关发放）
      done: false,                            // 三阶段全清 → 锁定到下周
      stageHeavy: 0                           // 当前阶段累计重伤人次（≥2 → 阶段中止）
    };
  }
}

/* —— 修正器确定性抽取 —— */
function rollWeeklyMods(seed){
  const rng = mulberry32(seed);               // 任意可植入种子 RNG
  const pick = pool => {                      // 按权重抽 1 条并从池中移除
    let r = rng() * pool.reduce((a, m) => a + m.w, 0);
    for(const m of pool){ r -= m.w; if(r <= 0) return m; }
    return pool[pool.length - 1];
  };
  const buffs = WEEKLY_DIVE.modifiers.pool.filter(m => m.kind !== 'debuff');
  const debs  = WEEKLY_DIVE.modifiers.pool.filter(m => m.kind === 'debuff');
  const b1 = pick(buffs);
  const d1 = pick(debs);
  const d2 = pick(debs.filter(m => m.id !== d1.id));
  return [b1.id, d1.id, d2.id];
}

   1. 解锁：miners.some(m => m.stars >= 1)

   4. 检定：T = base × HazardBonus + Σ mods.checkT；成功率 = P/(P+T) 再加 Σ mods.checkRate
   5. 事件权重：roll 前 evW 各键乘入权重表（数值配置表 §2.1）
   6. 账单：250 × HazardBonus × Π medBillMul；治疗时长 90 × H × Π medHoursMul

   8. 阶段通关：cleared[i]=true → 发 stage.rewards；全清 → done=true + completionBonus
      + campProgress('dive','',1)（战役"通关深潜"钩子）
