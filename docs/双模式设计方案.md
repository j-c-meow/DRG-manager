# 双模式设计方案（A 起草 · 待用户拍板 + B 数值核算 + C 视觉）

> 版本：v1.0 草案（2026-09-15）
> 背景：用户裁定当前单一时间流速（1 现实秒=1 游戏分钟）无法同时满足两类玩家——
> **纯挂机党**（放着不管，过会回来收钱）与**主动玩党**（打发时间，类开罗连续操作）。
> 本文档定义双模式、给出平衡框架与目标比值，供 B 核算数值、C 出视觉、A 实装。

---

## 一、两种模式定义

| | 模式 A：挂机模式（默认） | 模式 B：急行模式（类开罗） |
|---|---|---|
| 定位 | 主玩法。放着长草，回来收钱 | 主动玩法。连点操作，密集决策 |
| 任务时长 | 现状（300~480 游戏分 ≈ 5~8 现实分钟） | **÷30**（≈ 6~16 游戏分 ≈ 6~16 现实秒，用户口中的"10 秒做完"） |
| 事件 | 触发后弹窗，**可开"托管"自动选择** | 照常弹窗，**必须手选**（无托管） |
| 硝石消耗 | 基准公式，时间延长类选项**硝石减半** | 基准 ×4，时间延长类选项**额外大额硝石** |
| 产出 | 100% | **35%**（代币/墨菱石/墨菱油），稀有掉率 60%，XP 照常 |
| 深潜 | 照常 | **禁用**（周常大单不参与压缩） |
| 切换 | Header 双态开关，随时切换；**任务时长在派遣瞬间按当期模式锁定**（存入 d.mode），在途任务不受切换影响 → 无刷法 |

## 二、核心循环对比（为什么这样平衡）

```
挂机：时间本身是成本。任务 5~8 分钟，玩家等 → 事件是调味，收益是问候。
急行：时间不再是成本（10 秒），若产出不变 → 单位时间收益 30 倍 → 挂机沦为下策，模式崩坏。
杠杆三件套：
  ① 产出 ×0.35      → 直接压收益倍率到 ~10 倍
  ② 硝石消耗 ×4     → 把剩余倍率用硬资源吃掉（硝石不可速刷，日产能恒定）
  ③ 时间延长选项改为硝石付费 → 堵死"急行模式白嫖延长收益"的漏洞（用户点名的核心不对称）
```

**双模式互喂闭环（这是切换合理性的根基）**：
挂机任务是硝石**净产出**（耗 60 / 还 ≈90+，日产另有 25×24）→ 挂机攒硝石；
急行任务是硝石**净消耗**（耗 240 / 还 90）→ 硝石库存决定急行爆发额度；
没硝石 → 只能回挂机 → 硝石回满 → 再爆发。**急行的节奏限制器=硝石，挂机的奖励=随时能急行。**

## 三、平衡比计算框架（B 核算的目标）

**目标比值 R = 急行每小时实际收益 ÷ 挂机每小时收益 ≈ 1.5 ~ 2.0**
（主动玩理应更赚，但不应碾压——挂机是主体玩法）

```
挂机每小时收益 = (60 × 60 / 240任务分) × P × 1.0 ≈ 15P          （P=单任务基准收益）
急行每小时收益 = min(操作上限≈250任务/h, 硝石供给/240) × 0.35P
硝石日净供给 N* = 600(日产) + 挂机在线时长×15×净回30
急行可持续任务速率 = N* / 86400 × 摊平……（B 按连续流模型精算）
```

**B 需要产出的核算表**：
1. 硝石全闭环表：日产出（含挂机返还）vs 急行消耗 ×4 下的可持续任务数/日
2. R 值验算：按上述框架算出实际 R，若 >2 → 调 ×4 为 ×5 或产出 0.35→0.30；若 <1.5 → 反向
3. 时间延长选项硝石价目表（急行模式）：stay+30%→120 / bunker+25%→100 / save+20%→80 / slow+20%→80（基准建议，B 可调）
4. 挂机模式时间延长选项硝石减半的实现口径：是派遣费折扣还是选项退款（建议：选项触发时返还该次派遣硝石费的 50%，体感更直接）
5. 极端情况：硝石囤积爆仓（急行玩家攒一周一次性爆发的收益上限是否可接受）、硝石死锁（急行模式禁用后现有防死锁兜底仍生效）

## 四、挂机模式补强（用户点名两项）

### 4.1 事件自动选择（挂机券，用户拍板保持不变）
- **用户拍板（09-15）：挂机券保持现状**——3 小时限时托管（自动派遣 + 自动选事件 pri 项），不设免费常驻托管开关。
- A 已实测确认：券激活后 autoPlayStep 真实执行自动派遣（2 名以上空闲矿工即接单）与事件自动选择。
- 本节原"托管常驻开关"提案作废。

### 4.2 收益面板（离队简报）
- 触发：托管期间每累计 ≥60 游戏分自动累积；玩家回来点击"收益面板"（或托管结束自动弹出一次）。
- 内容（数据源=新增 S.idleReport 累计器，settle/log 钩子写入）：
  - 头部大数字：净赚代币（收入-支出）
  - 分组明细：完成任务 N 次／代币+X 墨菱石+X 墨菱油+X 硝石+X／稀有矿物掉落清单／事件处理清单（含托管自动选择的结果）／伤员与医疗支出／KPI 与战役进度变化
  - 底部一行趣味语（复用 egg_settle 池）
- 视觉：复用 lootIn 逐条弹出 + 分组色条；C 出 mockup。

## 五、急行模式规则明细（A 实装清单）

1. `S.mode ∈ {'idle','rush'}`，Header 切换器；派遣时 `d.mode = S.mode` 锁定。
2. 任务时长：rush 派遣时 `dur = max(6, round(基准 × 1/30))`；全局时钟流速不变。
3. 事件阈值照旧（按进度比例触发）→ 急行任务 10 秒内弹 1~2 事件，连续决策=开罗手感。
4. 产出乘区：settle 读 `d.mode==='rush'` → 代币/墨菱石/墨菱油 ×0.35，稀有掉率 ×0.6，XP/任务次数照常（鼓励急行练级）。
5. 硝石：rush 派遣费 ×4；时间延长选项按价目表加收（余额不足→按钮置灰+提示）；idle 模式时间延长选项返还 50% 派遣硝石费。
6. KPI 配额：吃 ×0.35 后的实际入账（天然平衡，无需特调）。
7. 战役/节日按次数计 1:1（B 核算后若偏快可加"急行模式计数 ×0.5"的调节阀，先不做）。
8. 深潜：rush 模式下开潜按钮置灰+提示"深潜只在挂机模式开放"。
9. 模式切换瞬间：在途任务按各自 d.mode 结算；弹出 toast 提示当前模式。
10. 收益面板与托管只在 idle 模式可用（rush 无托管，天然）。

## 七、风险与开放问题

1. **产出 0.35 的体感**：急行单任务收益缩水 65%，玩家可能觉得"亏"——收益面板要把"每小时收益"概念立起来（对比条：急行 vs 挂机每小时）。
2. **事件弹窗打断急行节奏**：10 秒任务弹 2 事件=强制停手——这正是开罗感，但若事件概率不变，急行的事件密度≈挂机的 30 倍（每小时）→ 确认 MEME slot 等概率是否需要微调（B 一并核算）。
3. **存档兼容**：S.mode/d.mode/idleReport 新字段走 load() 迁移，旧档默认 idle。
4. **已拍板（09-15）**：①挂机券保持不变（3 小时限时托管）②急行模式禁用加速——加速功能已整体退役（现状本就只剩暂停/×1，原"加速"标签已改为"时间"），急行模式落地时**整组时间控制隐藏**（spd-chip 钩子已预埋）③模式名"急行"待用户确认（备选：掘进/冲刺/开罗）。
