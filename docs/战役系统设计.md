# 战役系统设计草案（会话 A 认领，v0.1）

> 对应交接文档收发箱【认领】条目。实装在 游戏.html，本文档先定结构与数值。
> 与 B-3 武器模组系统的衔接点：**新武器只能通过对应战役上架**；模组抽卡的三提石任务也挂进战役奖励池。

## 一、结构

- 一名玩家同时只有 **1 条进行中的战役**（对齐原作），完成后自动接续队列中的下一条。
- 战役 = `{id, 名称, 简介, steps:[...], rewards:{...}}`，steps **顺序完成**（做完结 1 才开始结 2）。
- 每步 = `{type, target, need}`，进度由游戏事件钩子累计，落存档。

## 二、目标类型（state 机钩子）

| type | 触发钩子 | 示例 |
|---|---|---|
| mission_type | 任务完成（按任务类型计数） | "完成 3 次消灭任务" |
| mission_biome | 任务完成（按生物群系计数） | "在盐坑完成 2 次任务" |
| mission_hazard | 任务完成（危险 ≥H 计数） | "完成 4 次危险 ≥3 的任务" |
| mineral | 结算矿物入账 | "上缴 150 墨菱石" |
| rare | 稀有矿物掉落 | "掉落 20 个乌玛石" |
| elite_kill | ev_elite 猎杀成功 | "猎杀 1 只精英异虫" |
| license | 武器凭证升级 | "任意武器凭证升到 2 级" |
| deepdive | 深潜通关（联动 B-4） | "通关 1 次深潜" |

## 四、状态机（实装要点）

```js
S.campaign = { id:'cmp3', idx:0, prog:{}, done:[] };  // idx=当前步骤，done=已完成战役 id 表
// 钩子挂点：
// settle()      → mission_type / mission_biome / mission_hazard / mineral / rare
// resolveEvent()→ elite_kill
// buyLicense()  → license
// 深潜结算      → deepdive
// 每次 renderAll 前 campaignTick()：检查当前步是否达标 → 弹"战役目标完成"提示 → idx++
// 全部步骤完成  → 发奖励 → 弹"战役完成" → 队列下一条
```

## 五、UI（战役终端）

- 位置：任务板上方新增一条"当前战役"横幅（名称 + 当前目标进度条 + 奖励预览）。
- 完整列表放名册页新增"战役"子页：已完成战役（打勾灰显）+ 当前战役目标链。
- 完成弹窗：corporate 腔贺词（文案键 `cmp_*`，向 B-2 文案包风格看齐，主会话自写）。
