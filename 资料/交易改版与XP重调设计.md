## 一、交易系统改版

### 1.1 "买 max" 整数化

**现状**：买按钮固定 10/50 两档，手续费 `Math.ceil` 向上取整导致实际花费可能超出玩家预期，且小额外币余额买不起最小单位。

**改法**：
```js
// 新增"买 max"按钮（放清仓旁边对称位置）
const maxQty = Math.max(0, Math.floor(S.credits / Math.ceil(p * (1 + TRADE_FEE))));
html += '<button class="btn" data-mb="'+t.k+':max">买 max（'+maxQty+'）</button>';

// marketBuy 里处理 'max'
function marketBuy(k, qty){
  if(qty === 'max'){
    const p = S.market.prices[k]; if(!p) return;
    const unit = Math.ceil(p * (1 + TRADE_FEE));
    qty = Math.max(0, Math.floor(S.credits / unit));
    if(qty <= 0){ log('代币不足，买不起最小单位。', 'bad'); return; }
  }
  // ...后续逻辑不变
}
```

**验收点**：买 max 按钮 ≠ NaN，买完后 credits ≥ 0，买入数量为正整数。

### 1.2 硝石消耗随任务时长走

**现状**：派遣出发时 `nitra -= 60 * hc` 固定扣费，与任务时长无关——"夜班赶工"（时长 +10%）的负面感太弱，"轻装上阵"（硝石 ×1.5）的正面也感知不强。

**改法**：硝石消耗与任务时长挂钩。
```js
// 派遣出发时（openDispatch 或 doDispatch 内）：
const baseDur = 240;  // 参考时长：240 游戏分 = 4 现实分（基准任务）
const durFactor = dur / baseDur;  // dur = missionDur() 的返回值
const nitraCost = Math.round(60 * durFactor * hc * (clause && clause.id === 'thin' ? 1.5 : 1));
S.nitra -= nitraCost;
```

**效果对比**：

| 任务 | 时长（满编 4 人） | 旧硝石/人 | 新硝石/人 |
|---|---|---|---|
| 采矿探险 危1 | 240 分 | 60 | 60（基准） |
| 定点提取 危1 | 180 分 | 60 | 45（短任务省硝石） |
| 就地精炼 危3 | 390 分 | 60 | 98（长任务费硝石） |
| 执勤护送 危5 | 576 分 | 60 | 144（大活大消耗） |

**理由**：硝石消耗与时长挂钩后，"夜班赶工"（+10% 时长）和"轻装上阵"（×1.5 硝石）的负面条款真正生效；短任务省硝石、长任务费硝石，玩家在接单时要做硝石预算管理。硝石副产物公式 (50+40×hc)×(0.8+0.2×hazard) 不变，保证单人危 1 仍然净赚。

## 二、XP 曲线重调

### 2.1 现状问题

| 等级 | 当前需求（lv×100） | 危1 单 XP | 需要危 1 单数 |
|---|---|---|---|
| Lv1→2 | 100 | 20 | 5 |
| Lv5→6 | 500 | 20 | 25 |
| **Lv7→8** | **700** | 20 | **35** |
| Lv15→16 | 1500 | 20 | 75 |
| Lv25 上限 | — | — | — |

用户反馈：**Lv7 后升级要 35 个任务，感知极弱**。

### 2.2 新曲线

**XP 需求**：`lv × 60`（降 40%）
**XP 获得**：`25 × hazard`（升 25%）+ 事件成功奖励 +10 XP + 深潜双倍（50）

| 等级 | 旧需求（lv×100） | 新需求（lv×60） | 旧危1 单数 | 新危1 单数 | 降幅 |
|---|---|---|---|---|---|
| Lv1→2 | 100 | 60 | 5 | 3 | -40% |
| Lv5→6 | 500 | 300 | 25 | 15 | -40% |
| **Lv7→8** | **700** | **420** | **35** | **21** | **-40%** |
| Lv15→16 | 1500 | 900 | 75 | 45 | -40% |
| Lv25 上限 | 2400 | 1440 | — | — | — |

**深潜获得 XP**（双倍）：普通深潜 50×hazard，精英 50×hazard + 契合 +10。
→ 一场精英深潜三关全通 ≈ 150+180+210 = 540 XP（按危 4/5/5+ 计），中期升 2~3 级。

### 2.3 实装改动（游戏.html 两处）

```js
// ① 常规派遣结算（141896 行附近）：
mn.xp += 25 * m.hazard;    // 旧：20 * m.hazard

// ② 深潜派遣结算（140835 行附近）：
mn.xp += 50 * m.hazard;    // 旧：40 * m.hazard

// ③ 升级阈值（所有 while 循环）：
while(mn.xp >= mn.lv*60 && mn.lv < 25)    // 旧：mn.lv*100

// ④ 事件成功奖励（startEvent resolve 处，新增）：
mn.xp += 10;  // 事件成功 +10 XP
```

### 2.4 名册展示建议（配合升级感知）

- XP 文字 `40/300` 改为 **XP 进度条**（与士气条同款样式，绿色→金色渐变）
- 升级瞬间弹 `⬆ 侦察-1 升级！Lv.3 → Lv.4` 的 toast（3 秒消失）
